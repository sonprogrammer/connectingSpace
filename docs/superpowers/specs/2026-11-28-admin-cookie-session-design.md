# 관리자 7일 쿠키 세션 설계

## 목적

루트 Worker에 관리자 로그인·로그아웃·세션 확인 API를 추가하고, 관리자 문의 API가 같은 세션 쿠키를 검증하도록 연결한다.

## API 계약

- `POST /admin/auth/login`: `email`, `password`를 검증하고 7일 세션 쿠키를 발급한다.
- `POST /admin/auth/logout`: 세션 쿠키를 제거한다.
- `GET /admin/auth/session`: 유효한 세션이면 인증 상태와 만료 시각을 반환하고, 아니면 `401`을 반환한다.
- 관리자 문의 API는 동일한 쿠키에서 `admin:inquiries` 권한을 확인한다. 미인증은 `401`, 권한 부족은 `403`이다.

쿠키는 `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/admin`, `Max-Age=604800`을 사용한다.

로그인 본문은 4KiB로 제한한다. 로그인·로그아웃·문의 수정 요청은 요청 URL과 같은 `Origin`만 허용하고 인증 응답은 `Cache-Control: no-store`로 반환한다.

## 세션 방식 결정

HMAC-SHA-256으로 서명한 상태 비저장 쿠키를 사용한다. D1 세션 저장 방식은 개별 세션 폐기가 가능하지만, 이번 이슈에서 금지된 운영 D1 변경과 추가 읽기 비용이 필요하다. 서명 쿠키는 Worker 메모리에 의존하지 않고 D1 변경 없이 여러 인스턴스에서 검증할 수 있다.

로그아웃은 브라우저 쿠키를 제거하지만 이미 탈취된 쿠키를 만료 전에 개별 폐기하지 못한다. 긴급 전체 폐기는 세션 서명 키 교체로 처리해야 한다. 개별 폐기가 필요해지면 별도 이슈에서 D1 기반 세션 저장소를 도입한다.

분산 로그인 시도 제한은 Worker 메모리로 정확히 구현하지 않는다. 운영 배포 전 Cloudflare Rate Limiting 또는 승인된 영속 저장소를 별도 설정한다.

## 비밀 바인딩

실제 값은 저장소와 로그에 기록하지 않는다. 서버는 다음 Worker 비밀 바인딩만 읽는다.

- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`
- `ADMIN_SESSION_SECRET`

설정 누락은 세부 정보를 노출하지 않는 `500` 응답으로 처리한다.

## 제외 범위

- 실제 계정 또는 비밀값 설정
- 운영 D1 조회·변경·마이그레이션
- Cloudflare 배포와 대시보드 변경
- 관리자 로그인 화면
