# 공개 랜딩페이지 설계안

## 의도

커넥팅스페이스를 처음 방문한 고객이 서비스의 가치와 제작 방식을 빠르게 이해하고, 견적 요청 영역으로 이동하도록 공개 랜딩페이지를 구성한다.

## 목표

- 브랜드명과 핵심 메시지를 첫 화면에서 전달한다.
- 제작 철학, 제작 방식, 가격 안내, 포트폴리오, FAQ를 섹션별로 제공한다.
- 네비게이션과 주요 CTA가 문의 영역으로 이동한다.
- 다크 모드를 기본으로 제공하고 라이트 모드 전환 기반을 마련한다.
- 모바일과 데스크톱에서 콘텐츠가 잘리지 않도록 반응형 레이아웃을 제공한다.
- title, description, Open Graph metadata 구조를 제공한다.

## 제외 범위

- 실제 문의 API 연결과 문의 저장
- 관리자 화면과 인증
- 실제 포트폴리오 자료·공개 링크 확정
- 최종 로고와 색상 시스템 확정
- 가격 정책의 확정
- 복잡한 스크롤 애니메이션이나 외부 이미지 서비스 연결

## 선택한 접근

`widgets/landing` 아래에 정적 섹션을 책임별로 분리한다. 페이지 조합과 metadata는 `app`에서 담당하고, 다크·라이트 전환 상호작용은 `features/theme-toggle`의 Client Component로 한정한다. 문의 CTA는 현재 문의 API 대신 페이지 내 문의 영역 앵커로 연결한다.

## 화면 구조

1. 고정 헤더: 브랜드명, 주요 섹션 앵커, 테마 전환, 견적 요청 CTA
2. 히어로: 핵심 메시지, 보조 설명, 견적 요청 CTA, 작업 방향을 보여주는 추상 시각 요소
3. 제작 철학: 고객의 브랜드와 방문자를 연결한다는 원칙
4. 제작 방식: 상담·구조 설계·제작·검수의 단계형 설명
5. 포트폴리오: 실제 자료로 오인하지 않는 합성 프로젝트 카드
6. 가격: 확정 가격표가 아닌 상담 기반 안내와 범위 설명
7. FAQ: 정적 질문·답변 아코디언 또는 펼침 목록
8. 문의 CTA: 후속 문의 폼이 연결될 앵커 영역과 행동 유도
9. 푸터: 브랜드명과 기본 안내

## 콘텐츠와 스타일 결정

- 공개 문구는 이슈와 선행 기준에 맞춘 임시 콘텐츠로 작성하며, 확정되지 않은 가격·사례·정책은 사실처럼 표현하지 않는다.
- 색상은 다크 배경·밝은 본문·중립적인 강조 토큰으로 제한하고 최종 브랜드 색상으로 확정하지 않는다.
- 포트폴리오는 합성 데이터임을 카드 구조와 문구로 드러낸다.
- 기본 HTML landmark, 명확한 heading 순서, 키보드 포커스, 충분한 대비를 유지한다.
- `prefers-reduced-motion` 환경에서는 장식 애니메이션을 줄이거나 제거한다.

## 상태 경계

- 정적 랜딩 콘텐츠는 Server Component로 유지한다.
- 테마 전환은 브라우저 저장소와 `matchMedia`를 사용하는 Client Component로 분리한다.
- 문의 제출 상태와 서버 데이터는 이번 작업에 구현하지 않는다.

## 완료 기준

- 모바일·데스크톱 주요 콘텐츠가 잘리지 않는다.
- 네비게이션이 주요 섹션 앵커로 이동한다.
- 견적 요청 CTA가 문의 영역으로 이동한다.
- 기본 title·description·Open Graph metadata가 있다.
- 키보드 포커스와 기본 접근성이 유지된다.
- 랜딩페이지 렌더링 및 핵심 앵커·테마 상호작용 테스트가 있다.
