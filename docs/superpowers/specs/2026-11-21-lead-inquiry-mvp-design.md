# 견적 문의 확보 MVP 설계안

## 의도

다양한 업종의 사업자가 웹 제작 서비스 내용을 이해하고 견적 요청을 제출하도록 한다. 손 대표님은 관리자 페이지에서 문의를 확인하고 상담 진행 상태와 메모를 관리한다.

첫 MVP의 핵심 검증 대상은 AI 기능이 아니라 **공개 랜딩페이지에서 실제 문의가 발생하는지**이다.

## 목표

- 공개 랜딩페이지에서 웹 제작 서비스를 소개한다.
- 방문자가 짧은 견적 요청 폼을 제출한다.
- 관리자가 접수된 문의를 목록과 상세 화면에서 확인한다.
- 문의 상태와 상담 메모를 기록한다.
- FAQ는 랜딩페이지 하단의 정적 콘텐츠로 제공한다.
- 상담 후 계약서를 보내고 고객 승인을 받는다.
- 계약 승인 후 프로젝트를 만들고 고객에게 진행상황을 공유한다.
- 관리자가 직접 작성하거나 AI로 계약서 초안을 생성할 수 있다.
- 관리자가 버튼을 눌러 계약서·프로젝트 링크를 이메일로 보낼 수 있다.

## 제외 범위

- AI 상담봇
- AI 제안서 생성
- 웹사이트 코드 생성
- 고객의 자동 응답 이메일
- 고객용 로그인·마이페이지
- 결제·세금계산서 관리
- 아임웹·고객 도메인·서브도메인 자동 연결
- 업종별 맞춤 랜딩페이지
- 복잡한 프로젝트 관리

## 제약과 원칙

- 가능한 한 무료 운영을 우선한다.
- Cloudflare를 우선 플랫폼 후보로 사용한다.
- 관리자 사용자는 첫 MVP에서 손 대표님 1명으로 제한한다.
- 기존 `imweb` 프로젝트·저장소·DB·환경변수는 참조하거나 복사하지 않는다.
- 실제 고객 정보, 운영 DB, 비밀값, 실제 발송은 별도 승인 전까지 다루지 않는다.
- 확정되지 않은 가격, 월 관리 범위, 비용 부담 주체는 제품 요구사항으로 확정하지 않는다.

## 문의 폼

필수 입력:

- 업체명
- 담당자명
- 연락처
- 만들고 싶은 웹사이트나 문의 내용

선택 입력:

- 제작 희망 시기
- 예상 예산
- 현재 웹사이트 URL
- 참고 사이트

## 사용자 흐름

1. 방문자가 랜딩페이지에 들어온다.
2. 서비스 설명과 FAQ를 확인한다.
3. 견적 요청 폼을 작성한다.
4. 입력값 검증과 스팸 방지 절차를 통과한다.
5. 문의가 저장되고 접수 완료 화면이 표시된다.
6. 관리자가 관리자 페이지에서 신규 문의를 확인한다.
7. 관리자가 상태와 상담 메모를 갱신한다.
8. 관리자가 기본 계약서 템플릿으로 계약서를 작성·전송한다.
9. 고객이 보안 링크에서 계약서를 확인하고 이름·동의 체크·승인 버튼으로 승인한다.
10. 승인된 계약서 버전과 연결된 프로젝트가 생성된다.
11. 고객 전용 읽기 전용 링크가 발급되고 고객은 프로젝트 상태와 진행 업데이트를 확인한다.
12. 관리자가 계약서 또는 프로젝트 링크 이메일을 미리 보고 수정한 뒤 직접 전송한다.

## 관리자 상태

초기 상태는 `신규`로 저장한다. 관리자는 다음 상태 중 하나로 변경할 수 있다.

- 신규
- 상담 예정
- 상담 완료
- 견적 전달
- 종료

프로젝트 상태:

- 준비 중
- 제작 중
- 고객 검수
- 수정 중
- 완료
- 보류

프로젝트 진행 업데이트는 현재 상태와 별도로 누적 저장한다. 각 업데이트에는 상태, 메시지, 작성일을 포함한다.

## 데이터 관계

- 업체는 여러 문의를 가질 수 있다.
- 문의에는 고객 담당자 1명을 저장한다.
- 문의는 계약서가 없을 수도 있다.
- 전송된 계약서는 잠그고, 수정이 필요하면 새 버전을 만든다.
- 고객이 계약서를 승인한 경우에만 프로젝트를 만든다.
- 프로젝트는 승인된 계약서 버전과 연결한다.
- 프로젝트에는 여러 진행 업데이트와 고객 전용 링크가 연결된다.

## 고객 진행상황 링크

고객은 로그인 없이 프로젝트 전용 보안 링크로 읽기 전용 화면에 접근한다. 계약 승인 링크와 프로젝트 조회 링크는 분리한다. 관리자는 링크를 재발급하거나 차단할 수 있다.

고객에게 공개하는 정보:

- 프로젝트명
- 현재 상태
- 단계형 타임라인
- 관리자가 작성한 진행 메시지
- 마지막 업데이트 날짜

관리자 내부 메모, 원가, 다른 고객 정보는 공개하지 않는다.

## 계약서 작성과 AI 초안

계약서는 기본 템플릿을 직접 수정하거나 AI 초안으로 만들 수 있다. AI 초안은 관리자 입력값과 선택한 계약서 작성 지침을 사용한다. 금액, 일정, 제작 범위, 결제 조건 같은 핵심 값은 관리자 입력값을 그대로 사용한다.

AI 결과는 항상 초안이며, 관리자가 검토·수정하기 전에는 전송할 수 없다. 사용한 입력값, 작성 지침 버전, 모델 정보, 생성 결과를 관리자 전용 기록으로 저장한다. 테스트에서는 가상 고객 정보만 사용하고, 실제 운영에서는 전화번호·이메일·내부 상담 메모를 AI에 전달하지 않는다.

## 이메일 발송

계약서와 프로젝트 링크는 관리자가 버튼을 눌렀을 때만 이메일로 발송한다. 초기에는 인증된 기존 이메일 주소와 무료 트랜잭션 이메일 서비스를 사용하고, 나중에 도메인 이메일로 교체할 수 있다.

관리자는 발송 전에 기본 제목·본문을 미리 보고 수정할 수 있다. 발송 결과, 수신자, 발송 시각, 이메일 종류, 성공·실패 상태, 재발송 이력을 저장한다.

## 단계별 확장

### 1단계: 문의 확보 검증

랜딩페이지, FAQ, 견적 요청 폼, 접수 완료 화면, 관리자 문의 목록·상세·상태·메모를 구현한다.

### 2단계: 영업 관리 보강

상담 기록, 견적 정보, 후속 연락 일정, 제안서 작성 상태를 추가한다.

### 3단계: 관리자용 AI 기능

저장된 요청사항 템플릿과 업체 정보를 바탕으로 AI 제안서 초안을 생성한다.

### 4단계: 관리자용 코드 생성 기능

스타일 태그, 코드 초안 생성, 안전한 미리보기, 복사, 버전 관리를 추가한다.

## 미결정 사항

- 구체적인 기술 스택과 프론트엔드 구조
- Cloudflare 세부 서비스 조합과 무료 한도
- 관리자 1인 인증 방식
- 문의 알림 방식
- 개인정보 보관 기간·삭제 정책
- 도메인 구매 시점
- 가격과 월 관리 서비스 정책
- 계약서 문구와 승인 방식의 법적 검토
- 고객 진행 링크의 만료 정책
- AI 제공업체의 실제 고객 데이터 처리 정책
- 무료 이메일 발송 서비스와 발신 주소

## 개발 구조 원칙

- Next.js + TypeScript를 사용한다.
- Next 서버 컴포넌트는 정적 랜딩 콘텐츠와 SEO에 활용한다.
- 동적 데이터 처리는 Cloudflare Workers API가 담당한다.
- Cloudflare D1에 업체·문의·계약·프로젝트 데이터를 저장한다.
- 실용적인 FSD 구조를 사용한다.
- React Query는 서버 상태, Zustand는 전역 UI 상태를 담당한다.
- Tailwind CSS와 shadcn/ui를 사용한다.
- Zod 스키마를 웹과 API에서 공유한다.
- pnpm workspace 모노레포로 웹·API·공통 패키지를 관리한다.
- 컴포넌트와 훅은 읽기 쉽게 작게 유지하고 재사용한다.
- PR 전까지 전체 테스트를 반복 실행하지 않고, PR에서 전체 검증한다.
