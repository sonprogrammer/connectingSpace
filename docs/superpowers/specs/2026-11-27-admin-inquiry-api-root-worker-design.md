# 관리자 문의 API 루트 Worker 이전 설계

## 목적

이슈 #54에 따라 기존 구 Hono 구조의 관리자 문의 관리 요구사항을 루트 Next.js/vinext Worker 서버 경계에 구현한다. 관리자 화면이나 실제 로그인은 추가하지 않고, 문의 목록·상세·수정 API와 D1 데이터 경계만 제공한다.

## 포함 범위

- `GET /admin/inquiries`: 최신 접수순 목록, 상태·유형·검색 필터, 기본 20개·최대 100개 페이지네이션
- `GET /admin/inquiries/:inquiryId`: 문의 상세 조회
- `PATCH /admin/inquiries/:inquiryId`: 상태와 마지막 관리자 메모 수정, 빈 메모는 삭제
- 현재 `admin:inquiries` 인증 경계 재사용과 401·403 응답
- 루트 D1 저장소 확장, `0002` 증분 마이그레이션, OpenAPI 계약 갱신

## 제외 범위

- PR #37 병합 또는 구 `apps/api` 코드 수정
- 관리자 UI, 실제 관리자 계정, 영속 세션, 운영 D1, 배포
- 문의 상태 전환 제한과 관리자 메모 이력

## 접근 방식

루트 Worker의 Route Handler가 공유하는 관리자 문의 핸들러 팩토리를 만들고, 인증 공급자와 문의 저장소를 주입한다. 실제 라우트는 루트 D1 바인딩과 현재 인메모리 인증 공급자를 연결하며, 테스트는 합성 세션과 인메모리 저장소로 인증·검증·응답 계약을 확인한다. 저장소는 관리자 목록·상세·수정 계약을 확장하고 D1에서는 매개변수 바인딩, 검색 와일드카드 이스케이프, 최신순 정렬을 사용한다.

구 PR #37 코드를 그대로 가져오는 방식은 Hono `Context`와 구 저장소 인터페이스에 결합되어 현재 루트 구조에 맞지 않으므로 사용하지 않는다. 별도 관리자 Worker를 만드는 방식도 단일 Worker 이전 목표와 맞지 않아 제외한다.

## 안전·오류 경계

- 인증 검사를 입력·데이터 조회보다 먼저 수행한다.
- 문의 ID는 UUID 형식이 아니면 400, 형식은 맞지만 데이터가 없으면 404를 반환한다.
- 상태·유형·페이지·검색·수정 본문은 Zod로 검증한다.
- 내부 저장소 오류와 세부 정보는 500 공통 응답으로 감춘다.
- 운영 연결은 하지 않으며 로컬 D1과 합성 데이터만 사용한다.
