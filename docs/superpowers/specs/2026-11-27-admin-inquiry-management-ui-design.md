# 관리자 문의 관리 화면 설계

## 목적

관리자가 접수된 문의를 목록에서 찾고, 고객 문의 내용과 연락처를 확인하며, 상담 상태와 고객에게 노출되지 않는 내부 메모를 관리할 수 있게 한다.

## 범위

- `/admin`에 목록과 상세를 함께 배치한다.
- 기존 루트 Worker의 `GET /admin/inquiries`, `GET /admin/inquiries/:inquiryId`, `PATCH /admin/inquiries/:inquiryId`만 사용한다.
- 목록은 검색, 상태, 문의 유형 필터와 페이지 이동을 제공한다.
- 상세는 고객 문의 내용·연락처와 관리자 내부 메모를 분리한다.
- 상태와 내부 메모는 한 번에 저장한다.
- 로딩, 빈 상태, 일반 오류, 401 인증 필요, 403 권한 부족을 구분한다.
- 데스크톱은 목록·상세 2열, 모바일은 세로 흐름으로 제공한다.

## 제외 범위

- 로그인 화면, 세션 발급, 토큰 입력 UI
- Route Handler, 서버 인증, D1 계약 변경
- 계약서, 프로젝트 전환, 이메일, AI 기능
- 배포와 Cloudflare 설정 변경

## 제약과 결정

- `/admin/inquiries`는 Route Handler가 점유하므로 UI는 `/admin`에 둔다.
- 실제 계정과 영속 세션이 아직 없어 운영 HTTP 성공 흐름은 인증 후속 작업 전까지 확인할 수 없다. 화면은 API의 401·403을 받아 관리 콘텐츠를 차단한다.
- 서버 상태는 React Query로 관리하고, 목록 필터와 선택된 문의는 화면 지역 상태로 둔다.
- 고객에게 보여줄 별도 관리자 작성 필드는 현재 API에 없으므로 새 계약을 만들지 않는다. 고객이 작성한 `message`와 관리자 전용 `adminMemo`를 시각적으로 구분한다.

## 검토한 방식

1. `/admin` 단일 마스터-상세 화면: 기존 API 경로를 유지하고 모바일 대응이 단순해 이 방식을 사용한다.
2. `/admin/inquiries`에 페이지 추가: Route Handler와 URL이 충돌해 제외한다.
3. API를 `/api/admin/inquiries`로 이동: Backend·Cloudflare 범위를 침범하므로 제외한다.

## 완료 기준

- 인증되지 않거나 권한이 없는 사용자는 문의 데이터와 관리 기능을 볼 수 없다.
- 목록에서 문의를 선택하면 상세가 표시된다.
- 검색·상태·유형 필터와 페이지 이동이 API 쿼리에 반영된다.
- 상태·내부 메모 저장 후 목록과 상세 캐시가 갱신된다.
- 로딩·빈·오류 상태와 모바일·데스크톱 기본 사용성을 테스트한다.
