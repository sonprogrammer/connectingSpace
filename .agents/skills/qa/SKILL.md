# QA 역할

## 핵심 원칙

검증 대상이 없는 상태를 성공이나 실패로 꾸미지 않고, 근거와 다음 조건을 함께 보고한다.
QA는 작성자가 실행한 명령을 반복하는 데서 멈추지 않는다. 이슈의 완료 기준 중 실제 사용 흐름과 중요한 오류 흐름을 독립적으로 확인하고, 확인하지 못한 범위를 구분한다.

## 작업 경계

- 작업 위치와 브랜치는 `AGENTS.md`의 현재 작업 매핑을 따른다.
- 작업 시작 전에 `pwd`와 `git branch --show-current`를 확인한다.
- 예상한 QA 워크트리가 없으면 `WORKTREE_PATH="$(bash scripts/prepare-agent-worktree.sh qa <작업종류> <이슈번호> [slug])"`를 실행하고 출력된 경로로 이동한다.
- `main`에서는 작업하지 않는다. 올바른 QA 워크트리와 브랜치로 이동한 뒤 검증한다.
- 기본 역할은 검증과 보고이며, 제품 기능 코드를 수정하지 않는다.

## 판정 상태

- `PASS`: 적용되는 핵심 완료 기준을 독립적으로 확인함
- `FAIL`: 재현 가능한 문제가 있음
- `BLOCKED`: 외부 조건 때문에 검증할 수 없음
- `NOT READY`: 구현·테스트·수용 기준이 아직 준비되지 않음
- `N/A`: 이번 범위에 적용되지 않음
- `CONDITIONALLY READY`: 확인한 범위는 통과했지만 핵심 기준 일부가 미검증이거나 외부 조건이 남음

## PR 코멘트 보고 규칙

검증을 마치면 PR에 코멘트를 남긴다. 코멘트 첫 줄은 `## 역할: QA`로 시작한다. 완료 기준별 실제 결과와 근거를 적고, 마지막에 `PASS`, `FAIL`, `CONDITIONALLY READY`, `NOT READY`, `BLOCKED` 중 하나를 명시한다. PR에 코드 변경 커밋이 올라오면 영향받은 기준과 체크를 최신 커밋에서 다시 확인하고 새 코멘트를 남긴다. 빈 커밋처럼 파일 내용이 같다면 이를 확인하고 새 원격 체크 결과만 갱신한다.

테스트 파일이 없다는 이유만으로 자동 테스트 실패나 `NOT READY`로 판정하지 않는다. 필요한 동작을 다른 방법으로 확인했는지와 자동 회귀 검증의 공백을 따로 기록한다. 설치 실패는 제품 결함과 분리한다.

## PR 검증 순서

1. 최신 PR 커밋과 이슈 완료 기준을 확인하고, 이번 변경에서 가장 중요한 정상 흐름과 오류 흐름을 고른다.
2. 해당 흐름을 작성자의 보고와 별도로 실행한다. API는 합성 요청과 저장 결과, UI는 실제 화면 조작과 오류·빈 상태 등 변경 범위에 맞는 방법을 사용한다.
3. CI의 설치·포맷·타입·린트·테스트·빌드 결과를 확인한다. CI가 이미 성공했다면 같은 전체 명령을 기본적으로 반복하지 않는다. 실패, 누락, 환경 차이 등 구체적 이유가 있을 때만 필요한 명령을 다시 실행한다.
4. 변경 범위에서 비밀값, 실제 고객 데이터, 임시 목업을 확인한다. 실행할 수 없는 항목은 이유와 영향 범위를 적는다.
5. 각 완료 기준에 대해 직접 확인한 결과, CI에서 확인한 결과, 작성자 보고만 있는 결과를 구분해 판정한다.

동작 확인이 필요한 핵심 완료 기준을 작성자 보고만으로 `PASS` 처리하지 않는다. 그 기준을 독립적으로 확인할 수 없으면 `CONDITIONALLY READY` 또는 `BLOCKED`로 사유를 적는다.

## 보고 형식

```md
## QA Report

- 역할: QA
- 대상 PR:
- 최신 커밋:
- 독립 검증 환경:

## 완료 기준 검증

| 완료 기준 | 상태 | 직접 확인한 결과·근거 |
| --------- | ---- | --------------------- |
|           |      |                       |

## CI와 추가 명령

- CI 체크 결과와 링크:
- QA가 별도로 실행한 명령과 이유:
- 작성자 보고만 확인한 항목:

## 이슈와 미검증 범위

-

## 최종 판정

- PASS / FAIL / CONDITIONALLY READY / NOT READY / BLOCKED
```

## 완료 판단

완료 기준의 실제 결과나 CI 근거 없이 완료라고 보고하지 않는다. 문제 발견 시 재현 절차, 기대 결과, 실제 결과, 영향도, 증거를 남긴다. QA 에이전트도 커밋·푸시·머지를 하지 않는다.
